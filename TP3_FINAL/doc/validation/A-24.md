## Entrega y correspondencia de señales

| Señal de `cpu.v` | Función |

## Pruebas y oráculos

La primera sección del TB fuerza temporalmente las entradas internas de EX para aislar su lógica. Los destinos esperados son constantes independientes. Después libera todas esas señales y ejecuta doce escenarios a través del CPU real, sin forzar registros, datos reenviados ni controles. Las comparaciones se hacen después de estabilizar el flanco; hay watchdog independiente con `$fatal`.

| Caso | Resultado comprobado |
|---|---|
| BEQ/BNE, operandos iguales y distintos | Tomado/no tomado; `valid=0` inhibe ambos, JAL y JALR. Sin branch/jump no hay toma. |
| Otros funct3 de branch | Ninguna condición habilitada para 010…111. |
| PC=0x40, inmediato −4 | Destino 0x3C. |
| Base JALR 0x41, inmediato 0 | Destino 0x40 y enlace 0x44 con PC=0x40. |
| Base JALR 0x43 | Destino 0x42: conserva el bit 1. |
| Límites y wrap | Inmediatos B −4096/+4094, J −1048576/+1048574, JALR −2048/+2047; suma y enlace módulo 2^32. |
| Indexado de la imem real de B | Destinos 0x40 y 0x442 leen índice 16; 0xFFFFFFFE lee índice 255. Se conserva el destino byte completo en `w_target_ex`. |
| Escenarios 0…3 | BEQ/BNE tomado/no tomado con rs1 desde WB y rs2 desde MEM. Ambos operandos capturados valen cero y difieren de los reenviados. |
| Escenarios 4/5 | JALR usa base desde WB/MEM, respectivamente, y escribe enlace 12 en x5. |
| Escenarios 6/7 | JAL hacia atrás y hacia adelante; enlace 12 y rd=x0 sin escritura. |
| Escenarios 8/9 | Load→JALR y load→BEQ, una burbuja y dato desde WB; JALR escribe enlace 16, separado del destino 64. |
| Escenario 10 | Dos productores del mismo registro: MEM gana a WB para evaluar el branch. |
| Escenario 11 | Un intento de producir x0 no altera la base de JALR. |
| Pausa | Cada operación se retiene dos clocks sin avance; condición, destino, selectores y enlace se mantienen. |

La lectura de `target[9:2]` comprueba la política de indexado de B. La captura del destino en PC/debug se validará al conectar la redirección en A-25; A-24 comprueba que el PC público sigue el avance secuencial previsto. La prueba no interpreta ese avance como ejecución funcional de un programa con saltos.

La copia se crea renombrando únicamente el módulo como `cpu_a24_probe`, agregando esas dos salidas tras el include y sus dos asignaciones antes de `endmodule`. Se sintetiza con `tools/synth_ooc.tcl`, top `cpu_a24_probe`, las mismas dependencias RTL del target CPU y el encabezado externo de B. Ambas síntesis finalizaron sin errores ni warnings críticos, y sin detecciones de múltiples drivers, redes implícitas o latches. Cada log contiene 49 warnings: puerto halted constante antes de A-M07, bits altos de dirección dmem ignorados por contrato, paralelismo y límites de estimación de clock/skew y DRC en OOC. El CPU normal mantiene los recursos de A-23 porque la nueva lógica todavía no alimenta sus salidas; la copia observable permite verificar que el cálculo se sintetiza. ## Sensibilidad

Se generaron y compilaron copias temporales de `cpu.v`, sustituyendo solo una expresión en cada variante. Nunca se editó el RTL de trabajo para introducir el defecto. Cada corrida debió compilar correctamente y terminar con código distinto de cero y una línea de discrepancia `FAIL tb_branch_execute:`.

| Defecto introducido | Detección |
|---|---|
| Comparar operandos capturados en lugar de reenviados | BEQ/BNE del pipeline observan datos distintos de los esperados. |
| Usar PC IF en el destino relativo | El destino aislado y el del pipeline difieren de la constante esperada. |
| Usar base JALR capturada en lugar de reenviada | El destino JALR pierde el valor recién producido. |
| Borrar también el bit 1 de JALR | Destino 0x42 pasa incorrectamente a 0x40. |
| Omitir `w_valid_ex` | Se toma un salto de una burbuja. |
| Invertir condición BNE | Fallan los casos dirigido tomado/no tomado. |
