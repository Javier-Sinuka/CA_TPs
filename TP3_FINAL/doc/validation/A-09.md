# A-09 — dmem 256×32 con stores parciales

Fecha: 2026-11-04 (America/Argentina/Cordoba). Responsable: A. Rama `feature/TP3-phs-0_7`; commit de partida `c278c26078999802e26ea7d9cee0c141da635aa9`. Se aplicaron D-17, D-18 y D-19 del contrato A+B sin cambiar la interfaz pública del CPU.

## Implementación

Se creó `VIVADO/TP_FINAL/rtl/cpu/memory/dmem.v`. El índice de palabra es `i_addr[9:2]`; el array físico tiene 256 palabras y un vector dirty de 256 bits define cuáles existen lógicamente. El reset síncrono limpia dirty y bloquea el write físico. Los stores usan máscara de byte, half o word y mezclan sobre cero si la palabra estaba limpia. Las lecturas `lb/lh/lw/lbu/lhu` son combinacionales y extienden signo o cero después de seleccionar el carril. Las codificaciones de tamaño no soportadas devuelven cero y no habilitan store.

El RTL guarda `r_mem` y `r_dirty` en `always` separados. La escritura efectiva local es `i_en && i_we && !i_reset && r_store_valid`. La conexión futura de `i_en` a `w_adv` y de `i_we` a `valid_mem && mem_write_mem` pertenece a A-16; se registra en [decisiones.md](../documentation/cpu_decisiones.md). A-10 ampliará la cobertura de dirty y debug sobre este mismo módulo.

Se creó `VIVADO/TP_FINAL/tb/cpu/unit/tb_dmem.sv`, se registró en `tools/tbs.py` y se añadieron `dmem.v` y el TB a `TP_FINAL.xpr` en *Design Sources* y *Simulation Sources*. El TB usa un modelo independiente de 1024 bytes y dirty lógico, con seed fija `0x5EED0923` para 128 stores de regresión. Los ejemplos críticos se comparan además con constantes escritas a mano.

## Pruebas y resultados

Entorno: Linux, Python 3.12.3, Icarus Verilog 12.0 y Verilator 5.020. CWD: `Practico/TPs`.

| Comando | Resultado |
|---|---|
| `python3 TP3_FINAL/tools/run.py tb tb_dmem` | Exit 0; `PASS tb_dmem: 2908 checks`; log `TP3_FINAL/build/tb_dmem.log`. |
| `python3 TP3_FINAL/tools/run.py tbs` | Exit 0; seis testbenches locales PASS, incluidos A-07 y A-09. |
| `verilator --lint-only -Wall -Wno-fatal --top-module dmem TP3_FINAL/VIVADO/TP_FINAL/rtl/cpu/memory/dmem.v` | Exit 0; un aviso `UNUSEDSIGNAL` por `i_addr[31:10]`, ignorados intencionalmente por D-17. Sin truncamientos, latches ni múltiples drivers reportados. |
| `verilator --lint-only -Wall -Wno-fatal -Wno-UNUSEDSIGNAL --top-module dmem TP3_FINAL/VIVADO/TP_FINAL/rtl/cpu/memory/dmem.v` | Exit 0, sin otros warnings. |

Cobertura dirigida: cuatro carriles `sb/lb/lbu`, las dos mitades `sh/lh/lhu`, `sw/lw` desalineados, signo `0x80` y `0x8000`, solapamiento de stores, índice 255 sin cruzar a 0, wrap en 1024 y bits altos ignorados, pausa, write desactivado, tamaño inválido, reset prioritario y store parcial sobre palabra limpia. La regresión con modelo de bytes revisa cinco tamaños de load en los cuatro offsets después de cada store. El TB tiene watchdog y requiere exit 0, marcador PASS y ninguna línea FAIL.

La primera ejecución detectó un error del modelo del TB tras reset: conservaba bytes físicos antiguos al aplicar un store parcial. Se corrigió el oráculo para comenzar desde cuatro bytes cero cuando dirty estaba limpio; la salida observada del RTL (`0000AA00`) ya coincidía con el contrato. La corrida final, con los casos dirigidos ampliados, pasó con 2908 checks.
