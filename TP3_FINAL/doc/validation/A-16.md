## Implementación y mapa de señales

`rtl/memory_stage.v` reúne las implementaciones existentes de `dmem` y `mem_wb`, el mux de writeback y las habilitaciones efectivas. No agrega almacenamiento fuera de esos bloques y no modifica sus interfaces ni su política de direccionamiento/reset.

| Concepto | Señal/ruta real |
|---|---|
| Paquete de entrada | `cpu.w_*_mem`, salidas de `u_execute` |
| Memoria de datos | `cpu.u_memory.u_dmem` |
| Dirección/dato/tamaño de dmem | `w_result_mem`, `w_store_data_mem`, `w_funct3_mem` |
| Store habilitado | `u_memory.w_dmem_we = i_en && !i_reset && i_valid_mem && i_mem_write_mem` |
| Store físico | `u_dmem.w_we`, que aplica además el filtro de tamaño de A-09 |
| Dato capturado de load | `u_memory.w_load_data_mem`, cero si no es una carga válida |
| Registro hacia WB | `cpu.u_memory.u_mem_wb.r_*` |
| Selección WB | `w_wb_data = w_mem_to_reg_wb ? w_load_data_wb : w_result_wb` |
| Escritura de regfile habilitada | `w_regfile_we = w_adv && !i_reset && w_valid_wb && w_reg_write_wb && w_rd_wb!=0` |
| Escritura y bypass del banco existente | `u_decode.i_valid_wb/i_reg_write_wb/i_rd_wb/i_wdata_wb`, con permiso efectivo y dato WB |

MEM/WB captura PC, resultado/dirección, load extendido, rd, mem_to_reg, reg_write, halt y valid. Una carga conserva por separado dirección y dato: el mux de WB debe escribir el segundo. El dato de load sin uso se normaliza a cero; la dirección/resultado permanece visible. Una burbuja puede transportar datos, pero sus controles de escritura se anulan.

Reset síncrono domina enable, bloquea los efectos pendientes, invalida MEM/WB, limpia el banco de registros y limpia dirty lógico. No borra físicamente dmem; las palabras limpias se leen como cero y el próximo store parcial mezcla sobre cero. Sin avance se conservan los registros y no hay stores ni commit, aunque los controles pendientes estén activos. Los puertos debug no producen escrituras.

`cpu.v` sustituye las cuatro conexiones WB constantes por las salidas reales del nuevo módulo. El permiso efectivo llega al regfile de decode, que conserva sus protecciones locales. La memoria debug pública se conecta a dmem real. Los selectores 11…14 muestran PC WB, resultado/dirección, load e info WB; valid WB ocupa bit 3 de flags. Los campos ausentes de info WB siguen en cero con máscara `0x8600001F`.

El CPU conecta ahora las cinco etapas, pero no tiene forwarding, load-use, redirección ni detención HALT completos. `o_halted` sigue en cero hasta A-28, como prevé esta issue; no se añade una parada anticipada para hacer terminar las pruebas.

## Arnés MEM/WB y scoreboard de efectos

`tb_mem_wb` controla MEM directamente y conecta el WB del módulo al regfile real. Mantiene modelos independientes de registros, bytes y dirty. Los enables se observan antes del flanco; los datos y estado se comprueban después de las actualizaciones del flanco, con watchdog independiente.

| Caso | Resultado observado |
|---|---|
| Store MEM y escritura WB pendientes, pausa de 100 clocks | Cero aceptaciones durante pausa; una de cada tipo al reanudar. |
| Burbuja con controles basura sobre palabra limpia y sucia | Sin escritura ni dirty nuevo; la palabra sucia conserva su valor. |
| Carga de palabra | WB selecciona `0x89AB80FF` desde memoria, no la dirección cero. |
| LB/LBU/LH/LHU | Signo/cero y dato capturado coinciden con el modelo por bytes. |
| Stores parciales y wrap | Byte y half conservan carriles vecinos; dirección 1028 vuelve al índice 1. |
| Store de cero | Dirty se activa aunque el dato sea cero. |
| Store con tamaño no soportado | El permiso de CPU no causa escritura física ni dirty. |
| Destino x0 | Sin escritura arquitectónica aunque reg_write esté activo. |
| Reset con enable=0 y con enable=1 | Cancela store/commit pendientes, limpia registros/dirty e invalida WB. |
| Store parcial después de reset | Produce `0x00002200` sobre palabra lógica limpia, sin recuperar bytes antiguos. |
| Load inválido | `load_data_wb=0`, sin efectos aunque los controles de entrada soliciten lectura/escritura. |
| 128 combinaciones pseudoaleatorias de MEM y permisos | Estado, controles, mux, datos y contadores coinciden con el modelo. |
| Barridos debug | 32 registros y 256 palabras/dirty coinciden con los modelos mientras el sistema permanece pausado. |

El scoreboard cuenta stores físicos y escrituras de registros aceptadas; compara conteos observados con esperados y los reinicia en reset. Esto detecta escrituras repetidas durante una pausa aunque escribir el mismo dato no altere el valor visible. Cuenta efectos de escritura, no instrucciones retiradas.

## Integración CPU y programa sin riesgos

`tb_fetch` dejó de asumir operandos y registros siempre en cero. El modelo por ciclos captura operandos usando un banco de referencia que aplica el WB del mismo flanco antes de la lectura de ID, equivalente al bypass acordado. Conserva por separado los paquetes EX, MEM y WB y el estado de memoria. Así comprueba el cableado real sin exigir que los programas antiguos con RAW funcionen arquitectónicamente antes de implementar forwarding.

Además carga un programa corto independiente, sin riesgos, con tres NOP entre productor y consumidor cuando corresponde:

| Palabra | Instrucción significativa |
|---|---|
| 0 | `addi x1,x0,5` |
| 4 | `addi x2,x0,10` |
| 8 | `add x3,x1,x2` |
| 12, 13 | `sw x3,0(x0)`; `lw x8,0(x0)` |
| 17 | `addi x9,x8,-1` |
| 21, 22 | `sw x9,4(x0)`; `lw x10,4(x0)` |
| 26 | `addi x0,x0,99` |

Las demás palabras 0…31 son NOP. Tras 36 avances habilitados, un golden constante verifica los 32 registros: x1=5, x2=10, x3=x8=15, x9=x10=14; todos los restantes, incluido x0, en cero. Memoria[0]=15 y memoria[1]=14, ambas sucias; memoria[2]=0 y limpia. Las expectativas finales no se obtienen del scoreboard por ciclos ni del DUT. El fin es acotado, sin usar watchdog como éxito ni asumir HALT implementado.

El TB también conserva las pruebas previas de fetch, pausa, reset, memoria de instrucciones intacta, wrap, decode, EX/enlaces y debug, y agrega comprobación de campos y flags WB, commit de registros y memoria debug real. Este programa no cierra la cobertura completa de A-17 ni valida riesgos/saltos.

## Sensibilidad

Diez copias temporales con un defecto por corrida terminaron con exit 1 y FAIL. Las fuentes de trabajo no se mutaron:

- Invertir el mux de resultado/load de WB.
- Omitir valid MEM, enable o reset del permiso de store, en tres corridas separadas.
- Capturar la dirección como dato de load.
- Omitir enable del permiso de commit.
- No normalizar el load inválido.
- Marcar todo paquete MEM/WB como válido.
- Conectar el resultado/dirección WB al banco en lugar del valor final seleccionado, dentro del CPU.
- Conectar store_data como dirección de memoria dentro del CPU.

Las primeras ocho usaron `tb_mem_wb`; las dos últimas, `tb_fetch`, para comprobar la integración. Logs en `TP3_FINAL/build/a16_mutations/{wb_mux,store_valid,store_enable,store_reset,load_capture,wb_enable,load_valid,wb_occupancy,cpu_wb_value,cpu_mem_address}.log`. Para reproducir, copiar el módulo a un temporal, introducir solo el defecto indicado y sustituir su ruta en el comando que imprime el runner; conservar las demás fuentes y el TB, y ejecutar `vvp -n`, que debe fallar.
